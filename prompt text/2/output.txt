## Why it crashed

The build on your Mac is running **v1.11 code**. The clone was made before v1.12 landed, and the `git pull` you ran was from your home folder rather than inside `Vocab-Folio`, so it never updated. v1.11 had no `GoogleService-Info.plist` yet and its built-in fallback carried the *website's* Firebase app id (`1:…:web:…`). FirebaseCore on iOS only accepts `1:…:ios:…` ids, and when it sees anything else it raises an Objective-C exception that Swift can't catch — the `addAppToAppDictionary` line in your screenshot.

Fix on the Mac:

```
cd ~/Vocab-Folio
git pull
cd ios
xcodegen generate
open VocabFolio.xcodeproj
```

Then ⌘R. You should now see `GoogleService-Info.plist` listed under VocabFolio in the project navigator.

## The GitHub "secrets detected" email

That's the Firebase iOS API key. It's a client identifier, not a secret: Google's own docs say Firebase API keys identify the project and don't grant access to data — the Firestore rules do that. Every Firebase iPhone app ships this key inside its bundle, and the website's equivalent is already public in `config.js` on the live site. v1.13 removes the copy from the Swift file, but the alert is pinned to commit `b20cc50` and stays open until you dismiss it: open the alert → **Dismiss** → *False positive*.

Optional but worthwhile: in Google Cloud Console → APIs & Services → Credentials, open **iOS key (auto created by Firebase)** → Application restrictions → *iOS apps* → add `com.ottomanlabs.vocabfolio`. Do the same for **Browser key** → *Websites* → `russianvocab.cloudflare-passport599.workers.dev` and `localhost`. That limits the keys to your app and your site.

## Getting onto TestFlight

Your App Store Connect record is in place — "Prepare for Submission" is simply the state of an app that has no build yet. TestFlight (the Mac app and the tab in App Store Connect) shows nothing until Xcode uploads one:

1. After the pull and regenerate, set the run destination to **Any iOS Device (arm64)**.
2. **Product → Archive**. The Organizer opens when it finishes.
3. **Distribute App → TestFlight & App Store → Upload**, accepting the defaults.
4. Wait for the "has completed processing" email (5–20 minutes).
5. App Store Connect → *Vocab Folio: Word Cards* → **TestFlight** tab. Under *Internal Testing* press **+**, name a group, add yourself, tick the build. It appears in the TestFlight app on your phone within minutes.

The build carries version 1.13 (1) while the record says 1.0 — TestFlight doesn't mind. When you submit to the App Store later, edit the version in the record to match the build.
